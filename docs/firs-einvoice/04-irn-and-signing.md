# FIRS e-Invoice: IRN Generation & Digital Signing

Source: https://einvoice.nrs.gov.ng/docs (Version 1.1)

---

## 1. IRN (Invoice Reference Number) Generation

The IRN is a unique identifier for each invoice, generated by the System Integrator from three data points.

### Components

| # | Component | Source | Format | Example |
|---|-----------|--------|--------|---------|
| 1 | **Invoice Number** | Taxpayer's accounting system | Alphanumeric, no special characters | `INV001`, `INVOICE123` |
| 2 | **Service ID** | NRS e-Invoicing system (assigned on business enablement) | 8-char alphanumeric | `94ND90NR` |
| 3 | **Datestamp** | Invoice issue date | `YYYYMMDD` (numeric only) | `20240611` |

### Format

```
{InvoiceNumber}-{ServiceID}-{Datestamp}
```

**Example:** `INV001-94ND90NR-20240611`

### Rules

- **Invoice Number:** Alphanumeric only. No special characters (`!`, `@`, `#`, `$`, etc.).
- **Service ID:** Assigned by NRS when taxpayer is enabled. Unique per taxpayer. 8 characters.
- **Datestamp:** `YYYYMMDD` format. No dashes, slashes, or special characters.
- All three components are concatenated with hyphens (`-`).

### Baci Implementation

```typescript
function generateIRN(
  orderNumber: string,    // Baci order number (sanitized)
  serviceId: string,      // Merchant's NRS Service ID (stored in merchants table)
  issueDate: Date         // Invoice issue date
): string {
  // Sanitize order number: remove special chars, keep alphanumeric
  const invoiceNumber = orderNumber.replace(/[^a-zA-Z0-9]/g, '').toUpperCase();

  // Format date as YYYYMMDD
  const datestamp = issueDate.toISOString().slice(0, 10).replace(/-/g, '');

  return `${invoiceNumber}-${serviceId}-${datestamp}`;
}

// Example:
// generateIRN('ORD-001', '94ND90NR', new Date('2024-06-11'))
// → 'ORD001-94ND90NR-20240611'
```

## 2. Cryptographic Keys

Each taxpayer/business gets cryptographic keys from NRS for signing invoices.

### Downloading Keys

1. Log into NRS dashboard
2. Navigate to "My Account" tab
3. Click "Manage Cryptographic Keys"
4. Download `crypto_keys.txt`

### Key File Format

The `crypto_keys.txt` file contains base64-encoded values:

```json
{
  "public_key": "<base64-encoded public key>",
  "certificate": "<base64-encoded certificate>"
}
```

The public key is an **RSA public key** (PKCS#8 format, PEM-encoded under the base64).

### Baci Implementation

Store merchant's crypto keys securely:

```sql
ALTER TABLE merchants ADD COLUMN IF NOT EXISTS firs_public_key TEXT;
ALTER TABLE merchants ADD COLUMN IF NOT EXISTS firs_certificate TEXT;
-- Store the base64-encoded values from crypto_keys.txt
-- These are used for signing invoices and generating QR codes
```

## 3. Invoice Signing & QR Code Generation

After generating the IRN, the invoice must be digitally signed and a QR code generated for verification.

### Step-by-Step Signing Process

#### Step 1: Extract Keys from crypto_keys.txt

```bash
# Extract the public key
jq -r '.public_key' crypto_keys.txt > public_key.txt

# Decode base64 to PEM format
openssl base64 -d -in public_key.txt -out public_key.pem

# Result: RSA public key in PEM format
# -----BEGIN PUBLIC KEY-----
# (base64-decoded key data)
# -----END PUBLIC KEY-----
```

#### Step 2: Prepare the Signing Payload

The payload is the IRN concatenated with a **UNIX timestamp**, separated by a period (`.`):

```
{IRN}.{UNIX_TIMESTAMP}
```

**Example:** `INV001-345SFG-20241011.1731618237`

> **Important:** This is NOT just the IRN. You must append the current UNIX timestamp.

Then create a JSON payload combining the timestamped IRN with the certificate:

```json
{
  "irn": "INV001-345SFG-20241011.1731618237",
  "certificate": "VVhrallFNVZUdDV0eUJmYWV1RmYwUXJRNEhTdXlhcU1pOGZsWF35sfhWRT0="
}
```

#### Step 3: Encrypt with RSA Public Key

```bash
# Encrypt the IRN + certificate payload using RSA public key
openssl pkeyutl -encrypt -inkey public_key.pem -pubin -in data.json -out encrypted_data.bin

# Convert encrypted binary to base64 for QR code
base64 -i encrypted_data.bin -o encrypted_data.txt
```

#### Step 4: Generate QR Code

```bash
# Generate QR code PNG from the base64 encrypted data
qrencode -o qr_code.png -t PNG < encrypted_data.txt
```

The QR code can be scanned by the NRS MBS360 mobile app for verification.

### Command Summary

| Action | Command |
|--------|---------|
| Extract & decode public key | `jq -r '.public_key' crypto_keys.txt \| tee public_key.txt \| openssl base64 -d -out public_key.pem` |
| Create signing payload | `jq --arg irn YOUR_IRN '{ irn: $irn, certificate: .certificate }' crypto_keys.txt > data.json` |
| Encrypt payload | `openssl pkeyutl -encrypt -inkey public_key.pem -pubin -in data.json -out encrypted_data.bin` |
| Convert to base64 | `base64 -i encrypted_data.bin -o encrypted_data.txt` |
| Generate QR code | `qrencode -o qr_code.png -t PNG < encrypted_data.txt` |

### Official npm Package

NRS provides an official npm package to simplify integration:

```bash
npm install firs-einvoicing
```

The `firs-einvoicing` package handles invoice decryption, QR code generation, and other integration tasks.

### Encrypted Invoice Format

Signed/encrypted invoices from FIRS use **AES-256-CBC** encryption (Laravel-style). The payload is a base64-encoded JSON object:

```json
{
  "iv": "+mPORUOCBynQwsRn159TXg==",
  "value": "<base64-encoded AES-256-CBC ciphertext — the encrypted invoice data>",
  "mac": "edbb43d5049fdeec197935665204a178918df7d3aab0993fd1582a61b8bdc0e5",
  "tag": ""
}
```

| Field | Description |
|-------|-------------|
| `iv` | AES initialization vector (base64-encoded, 16 bytes) |
| `value` | The encrypted invoice JSON (base64-encoded AES-256-CBC ciphertext) |
| `mac` | HMAC-SHA256 message authentication code for integrity verification |
| `tag` | Empty string (used for AES-GCM mode, not applicable in CBC mode) |

**Decryption:** Use the `firs-einvoicing` npm package or decrypt manually with Node.js `crypto`:

```typescript
import crypto from 'crypto';

function decryptFirsInvoice(encryptedPayload: string, key: Buffer): string {
  const payload = JSON.parse(Buffer.from(encryptedPayload, 'base64').toString());
  const iv = Buffer.from(payload.iv, 'base64');
  const value = Buffer.from(payload.value, 'base64');

  // Verify MAC before decryption
  const macPayload = Buffer.from(payload.iv + payload.value).toString();
  const calculatedMac = crypto
    .createHmac('sha256', key)
    .update(macPayload)
    .digest('hex');

  if (calculatedMac !== payload.mac) {
    throw new Error('MAC verification failed — payload may be tampered');
  }

  // Decrypt with AES-256-CBC
  const decipher = crypto.createDecipheriv('aes-256-cbc', key, iv);
  let decrypted = decipher.update(value);
  decrypted = Buffer.concat([decrypted, decipher.final()]);

  return decrypted.toString('utf8');
}
```

> **Note:** The decryption key comes from the merchant's cryptographic keys downloaded from the NRS dashboard. The `firs-einvoicing` package handles this automatically.

### Signing Endpoint (Server-side via FIRS API)

After local QR code generation, submit to FIRS for official signing:

```
POST {base_url}/api/v1/invoice/sign
```

This returns:
- **CSID** (Cryptographic Stamp Identifier) — the official FIRS digital stamp
- **Signed invoice data**

### Baci Integration Flow

```
1. Merchant creates order in Baci
2. Baci generates IRN: {sanitized_order_number}-{service_id}-{YYYYMMDD}
3. Baci builds UBL invoice JSON from order data (see 01-invoice-schema.md)
4. POST /api/v1/invoice/validate → validates schema
5. POST /api/v1/invoice/sign → gets CSID + signed invoice
6. Create signing payload: {IRN}.{unix_timestamp} + certificate
7. Encrypt with merchant's RSA public key
8. Generate QR code from encrypted base64 data
9. Embed QR code in invoice PDF
10. Store signed invoice + CSID in database
11. POST /api/v1/transmit → send to FIRS/buyer
```

### Baci TypeScript Implementation (Conceptual)

```typescript
import crypto from 'crypto';

function createSigningPayload(irn: string, certificate: string): string {
  const timestamp = Math.floor(Date.now() / 1000); // UNIX timestamp
  const payload = JSON.stringify({
    irn: `${irn}.${timestamp}`,
    certificate,
  });
  return payload;
}

function encryptWithPublicKey(payload: string, publicKeyPem: string): string {
  const encrypted = crypto.publicEncrypt(
    {
      key: publicKeyPem,
      padding: crypto.constants.RSA_PKCS1_OAEP_PADDING,
    },
    Buffer.from(payload)
  );
  return encrypted.toString('base64');
}

// The base64 encrypted string is what goes into the QR code
```

## Baci Database Schema Additions

```sql
-- Track FIRS invoice submissions
CREATE TABLE IF NOT EXISTS firs_invoices (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  merchant_id UUID NOT NULL REFERENCES merchants(id),
  order_id UUID NOT NULL REFERENCES orders(id),
  irn VARCHAR(100) NOT NULL,           -- Generated IRN
  csid VARCHAR(255),                    -- Cryptographic Stamp ID (from FIRS signing)
  invoice_type_code VARCHAR(10) NOT NULL DEFAULT '381',
  status VARCHAR(20) NOT NULL DEFAULT 'draft',  -- draft, validated, signed, transmitted, confirmed
  firs_response JSONB,                 -- Full response from FIRS API
  signed_at TIMESTAMPTZ,
  transmitted_at TIMESTAMPTZ,
  confirmed_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),

  UNIQUE(merchant_id, irn)
);

ALTER TABLE firs_invoices ENABLE ROW LEVEL SECURITY;

CREATE POLICY "merchants_own_firs_invoices" ON firs_invoices
  FOR ALL USING (auth.uid() = merchant_id);

CREATE INDEX idx_firs_invoices_order ON firs_invoices(order_id);
CREATE INDEX idx_firs_invoices_irn ON firs_invoices(irn);
CREATE INDEX idx_firs_invoices_status ON firs_invoices(status);
```
