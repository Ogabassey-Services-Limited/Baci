## Surround Sound Strategy

Build entity identity through distributed corroboration across multiple domains.

### The Principle

Search engines build entity understanding from multiple sources. A single website saying "Brand X is the best" is weak. Ten websites saying it creates consensus.

### Implementation Steps

1. **Create Corroboration Pages**
   - Third-party profiles (Crunchbase, Golden.com, LinkedIn Company)
   - Industry directory listings
   - Press mentions and features
   - Guest posts on relevant sites
   - Social media profiles with consistent descriptions

2. **Build Consensus Signals**
   - Use identical entity descriptions across all platforms
   - Same Name, Address, Phone (NAP) everywhere
   - Consistent brand messaging and positioning
   - Same key entity attributes mentioned

3. **Reinforce Through Co-occurrence**
   - Ensure brand appears alongside target topic entities
   - Build associations with authoritative entities in your space
   - Create N-gram patterns: "[Brand] + [Topic]" across web

### Example for OgaBassey:
- Crunchbase profile: "Nigerian electronics retailer"
- Google Business Profile: Same description
- LinkedIn: Same description
- Press mentions: "OgaBassey, the Nigerian electronics retailer..."
- Guest posts: Reference "OgaBassey" alongside "phones Nigeria"

## Mention Strategy

**"Mention-building should be seen as important as link-building."**

### What Mentions Pass

Unlike links (which pass PageRank), mentions pass:
- **Relevance signals** — Topic association
- **Co-occurrence data** — N-gram relationships
- **Semantic embeddings** — Vector space positioning
- **Entity recognition** — Knowledge graph entries

### Implementation

1. **Press Releases**
   - Mention brand alongside target terms
   - "OgaBassey, Nigeria's trusted phone retailer, announces..."
   - Distribute to news aggregators and industry sites

2. **N-gram Building**
   - Identify desired N-grams: "OgaBassey phones", "buy phones OgaBassey"
   - Create content across web featuring these combinations
   - Monitor what N-grams appear around your brand
   - Address negative N-gram associations

3. **Topical Entry Creation**
   - "Topical entries" = phrases reflecting topicality
   - Build mentions with brand + topical entries
   - Example: "OgaBassey BNPL phones Lagos"

### Critical Rule

**Site-wide N-grams must match external co-occurrences.**

If your site says "affordable phones" but external mentions say "cheap phones" — misalignment signals spam or inconsistency.

## Knowledge Domains

Google classifies sources within Knowledge Domains as **Experts**, **Apprentices**, or **Laypersons**.

### What's a Knowledge Domain?

Areas with specific:
- Query patterns
- Entity types
- Layout requirements
- User satisfaction models

### Domain-Specific Quality

**Critical insight**: Quality parameters differ by domain.

| Domain | High Bounce = | Low Bounce = |
|--------|---------------|--------------|
| Currency/Exchange | Success (got answer) | Failure (confused) |
| Education | Failure (didn't engage) | Success (learning) |
| E-commerce | Mixed (depends on intent) | Mixed |

### Becoming a Domain Expert

1. **Cover domain query patterns** — All question types users ask
2. **Use domain entity types** — Proper terminology and entities
3. **Match domain layouts** — Expected page structures
4. **Satisfy domain user models** — What success looks like

### Categorical Quality

Google assigns **categorical quality** per source section. Different website sections can have different quality scores.

- Site might be "Expert" for phones, "Layperson" for laptops
- Focus on achieving Expert status in core topics first
- Expand only after establishing domain expertise

## Seed Sites and Source Shadowing

### Seed Sites

**Seed Sites** (high SourceRank sites) anchor Google's semantic structure.

- Wikipedia is the canonical example
- Industry-specific: WebMD for health, Investopedia for finance
- Proximity to Seed Sites in link graphs matters
- Google uses Seed Sites to validate information

### Representative Sources

Google chooses **representative sources** for topics. Other sources rank based on similarity to the representative.

### Source Shadowing

One website can appropriate another's rankings:
1. Identify representative source for target topic
2. Build similar signals (topical coverage, authority patterns)
3. Gradually become the new representative

**This is why 27 articles can outrank established sites** — by perfectly matching the semantic pattern of what a representative should look like.

## Frame Semantics

### What It Is

Frame Semantics explains how language evokes mental structures. Every predicate (verb) activates a "frame" with expected entities and relationships.

### Application to SEO

**Verb choice signals context:**

| Verb | Expected Frame/Context |
|------|----------------------|
| "examine" | Investigation, analysis, research |
| "consume" | Food, media, resources |
| "build" | Construction, creation, development |
| "purchase" | Commerce, transaction, retail |

### Practical Use

1. **Choose verbs deliberately**
   - "Buy phones" (transactional frame)
   - "Compare phones" (evaluation frame)
   - "Understand phones" (educational frame)

2. **Maintain frame consistency**
   - If page is transactional, use transactional verbs throughout
   - Don't mix incompatible frames

3. **Connect frames via predicates**
   - Link articles through verb relationships
   - "Learn about phones" → "Compare phones" → "Buy phones"

## Ranking Signal Dilution

When multiple pages compete for the same canonical query, each weakens the other.

### Key Terminology

| Term | Definition |
|------|------------|
| **Canonical Query** | Best summative version representing similar queries |
| **Represented Query** | Query a page is designed to rank for |
| **Representative Query** | Query Google associates with the page |

### Dilution Causes

- Two pages targeting identical canonical queries
- Content similarity exceeding **6% threshold**
- URL parameters creating near-duplicates
- Incorrect canonicalization

### Prevention

1. **Check content similarity** — Use tools to compare pages
2. **Distinct anchor texts** — Never use same anchor for different pages
3. **Clear query separation** — Each page = distinct canonical query
4. **Consolidate when needed** — Merge competing pages
