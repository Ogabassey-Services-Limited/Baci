## Verdict
This PR successfully removes redundant Suspense boundaries around the metadata marker. However, the implementation introduces a Core Web Vitals violation on the FAQ page and inconsistently applies the Suspense pattern, meaning the catalog pages will still block the metadata marker from committing early.

## Findings
- **High severity**: Wrapping `FAQContent` in `<Suspense fallback={null}>` violates the Baci Core Web Vitals requirement. Since `FAQContent` contains primary visible storefront content, a `null` fallback causes the page to render blank initially, followed by an abrupt Cumulative Layout Shift (CLS) when the content resolves.
  - `apps/web/src/app/(storefront)/[slug]/(content)/faq/page.tsx`
- **Medium severity**: The PR goal of keeping visible content behind a Suspense boundary (so the metadata marker can commit early) was applied to `FAQContent` but omitted for `CategoryPageContent` and `ProductsPageContent`. If these components await data or unwrapped `params`, they will suspend the entire page, blocking `StorefrontDynamicMetadataMarker` from streaming to the client.
  - `apps/web/src/app/(storefront)/[slug]/(catalog)/[category]/page.tsx`
  - `apps/web/src/app/(storefront)/[slug]/(catalog)/products/page.tsx`

## Suggested next steps
- Replace `<Suspense fallback={null}>` around `FAQContent` with a proper skeleton UI component (e.g., `<FAQContentSkeleton />`) to reserve space and prevent layout shifts.
- Apply the same pattern to the catalog routes by wrapping `CategoryPageContent` and `ProductsPageContent` in explicit `<Suspense>` boundaries using their respective skeleton fallbacks.
- Add regression tests to `[category]/page.test.tsx` and `products/page.test.tsx` mirroring the one added for the FAQ page, verifying that the metadata marker streams outside of the suspended catalog content.
