## The 5 Fundamentals

Every functioning topical map requires these five elements:

### 1. Source Context
**What:** Why your brand should exist in SERPs. The unique value proposition.

**Questions to answer:**
- What makes this source uniquely qualified for this topic?
- Why would a search engine choose this source over others?
- What's the brand's relationship to the topic domain?

**Example:**
- OgaBassey: "Trusted Nigerian gadget retailer with flexible payment options and local expertise"
- usebaci: "E-commerce platform built specifically for African merchants"

### 2. Central Entity
**What:** The main entity that appears site-wide and defines the semantic center.

**Questions to answer:**
- What single entity does everything on the site relate to?
- If the site were a knowledge graph node, what would it be?

**Example:**
- OgaBassey: "Consumer electronics retail" or "Gadgets"
- usebaci: "E-commerce platform" or "Online store builder"

### 3. Central Search Intent
**What:** The primary intent the site serves across all content.

**Intent Types:**
- Informational (learn about)
- Commercial (compare, evaluate)
- Transactional (buy, sign up)
- Navigational (find specific thing)

**Example:**
- OgaBassey: Transactional (buy gadgets) + Commercial (compare prices)
- usebaci: Commercial (evaluate platforms) + Transactional (sign up)

### 4. Core Section
**What:** Primary topical coverage directly related to central entity.

**Characteristics:**
- Directly monetizable topics
- High search volume queries
- Closest semantic relationship to central entity

**Example:**
- OgaBassey Core: Smartphones, laptops, tablets, accessories, prices, comparisons
- usebaci Core: Features, pricing, integrations, use cases, comparisons

### 5. Outer Section
**What:** Supporting topics that build authority but are one step removed.

**Characteristics:**
- Build topical authority through breadth
- Support core topics semantically
- May have lower direct commercial value

**Example:**
- OgaBassey Outer: Tech news, buying guides, phone tips, Nigerian tech market
- usebaci Outer: E-commerce trends, merchant success stories, digital business education

## Token Insertion Methodology

Token Insertion is the process of identifying all probable word distributions in documents and queries for your domain.

### Process:

**Step 1: Identify Verb-Noun Relations**
List all relevant verb + noun combinations for your domain:
```
E-commerce example:
- build store
- process payments
- manage inventory
- ship orders
- track sales
- grow business
```

**Step 2: Generate Query Variations**
For each verb-noun pair, expand into full query space:
```
"build store" expands to:
- how to build online store
- build store Nigeria
- build store without coding
- build store free
- build store Shopify alternative
- build store for small business
```

**Step 3: Map to Document Templates**
Create document templates that cover query clusters:
```
Query cluster: "build store [context]"
Document template: "How to Build Your Online Store [Context]"
- Covers: free, Nigeria, without coding, small business, etc.
```

### Allocation Guidelines:
- **Core Section:** 60-70% of content
- **Outer Section:** 30-40% of content

### Core Section Priorities:
1. Money pages (products, pricing, services)
2. High-intent commercial content
3. Direct comparison content
4. Feature/benefit content

### Outer Section Priorities:
1. Educational content building expertise
2. Industry news and trends
3. Broader topic coverage
4. Trust and authority signals

## Creating the Topical Map

### Step-by-Step Process:

**1. Define Central Entity**
```
Central Entity: [Your main topic]
```

**2. List All Related Entities**
Use brainstorming, competitor analysis, Knowledge Graph, autocomplete:
```
Related Entities:
- Entity A (relationship: parent)
- Entity B (relationship: child)
- Entity C (relationship: peer)
- Entity D (relationship: attribute)
```

**3. Map Entity Attributes**
For each entity, list all attributes users query:
```
Entity: Samsung Galaxy A35
Attributes: price, specs, battery, camera, display, storage, color, availability, warranty, reviews, comparisons
```

**4. Generate Questions**
For each entity-attribute pair:
```
Entity: Samsung A35 | Attribute: battery
Questions:
- What is Samsung A35 battery capacity?
- How long does Samsung A35 battery last?
- Is Samsung A35 battery good?
- Samsung A35 battery vs iPhone 14
```

**5. Assign to Core or Outer**
```
CORE (directly monetizable):
- Product pages
- Comparison pages
- Pricing pages
- Feature pages

OUTER (authority building):
- Buying guides
- Industry education
- News/updates
- How-to content
```

**6. Identify Quality Nodes**
Mark 5-10 documents as Quality Nodes (see below).

**7. Map Internal Linking Structure**
Define contextual bridges between topics.

## Quality Nodes Strategy

Quality Nodes are anchor documents that change search engine's quality score assignment for your entire domain.

### Characteristics of Quality Nodes:
- 3-5x more detailed than average content
- Comprehensive coverage of topic
- Original research, data, or insights
- Expert authorship signals
- Multiple media types (text, images, videos)
- High information density

### Quality Node Placement:
- **Link from homepage directly**
- Place in core section of topical map
- Interlink heavily with related content
- Update regularly to maintain freshness

### Quantity:
- Start with 5-10 Quality Nodes
- Each should be "best on internet" for that topic
- Quality > Quantity

### Example Quality Nodes:
- OgaBassey: "Complete Smartphone Buying Guide Nigeria 2024"
- usebaci: "Ultimate Guide to Starting an Online Store in Africa"

## Prioritization Framework

### Publishing Velocity Pattern (Critical)

**Follow this exact acceleration pattern:**

| Phase | Timing | Frequency |
|-------|--------|-----------|
| Phase 1 | Days 1-20 | 1 article every 3 days |
| Phase 2 | Days 21-30 | 1 article every 2 days |
| Phase 3 | Days 31-50 | 1 article daily |
| Phase 4 | Days 51+ | Up to 3 articles/day |

**Why this pattern works:**
- Starting too fast triggers spam detection
- Gradual acceleration signals investment to Googlebot ML
- Builds trust before scaling
- Allows quality maintenance during ramp-up

### Expected Timeframes

| Milestone | Timeframe |
|-----------|-----------|
| First ranking signals | 28-30 days |
| Initial ranking phase | 20-45 days |
| Re-ranking phase | 30-65 days |
| First featured snippets | 60-90 days |
| Significant traffic growth | 115-123 days |
| Full topical authority | 5-6 months |

### If Starting Fresh (New Domain):

**Week 1-2:**
1. Define 5 fundamentals
2. Create topical map structure
3. Write 3-5 Quality Nodes
4. Establish homepage linking to Quality Nodes

**Month 1:**
1. Publish 20-30 core section documents
2. Ensure contextual internal linking
3. Monitor indexing and initial rankings

**Month 2-3:**
1. Expand to outer section
2. Continue core section depth
3. Build historical data through consistent publishing

### If Existing Site (Recovery/Growth):

**Week 1:**
1. Audit ranking state (positive/negative)
2. If negative: clean up first (remove thin pages, fix technical)
3. Map existing content to topical map structure

**Week 2-4:**
1. Identify and fill topical gaps
2. Create missing Quality Nodes
3. Restructure internal linking

**Month 2+:**
1. Systematic expansion
2. Historical data building
3. Authority signal improvement

### The 27-Article Pattern

Koray has demonstrated outranking established authorities with just 27 articles. The key:
- All 27 are high-quality, comprehensive
- Perfect topical coverage for specific query cluster
- Strong internal linking creating semantic network
- Consistent EAV structure throughout
- Quality Nodes anchoring the network

This works because **Topical Authority = Coverage × Quality**, not volume.
