## 2026-05-24 - [Storefront Order Type Mismatch]
**Learning:** Storefront (public) API endpoints often return slightly different shapes than internal dashboard APIs (e.g., aliased fields like `shipping_cost` vs `shipping_fee`, missing `created_at`). Components should use specific interfaces (like `StorefrontOrder`) rather than reusing internal shared types directly if the API transforms the data. Also, database JSON columns like `shipping_address` may be returned as objects or strings depending on the query/RPC, requiring union types (`string | Record<string, unknown>`) and safe rendering logic in UI components.
**Action:** Always verify the actual API response shape (via network tab or code inspection) before assuming shared types apply to storefront components. Use `StorefrontOrder` for public-facing order details and handle JSON column variability.
