## 2025-02-14 - Fix incomplete HTML escaping causing XSS risk
**Vulnerability:** A custom `escapeHtml` function relied on assigning to `div.textContent` to escape text, which failed to escape single and double quotes. When this function's output was injected into HTML attributes (e.g., `src="${escapeHtml(url)}"`), an attacker could provide a payload containing double quotes to break out of the attribute and inject arbitrary event handlers (like `onerror="alert(1)"`).
**Learning:** `div.textContent = str` does not encode quotes (`"`, `'`). It only encodes `<`, `>`, and `&`.
**Prevention:** Always use comprehensive regex-based escaping (replacing `&`, `<`, `>`, `"`, and `'`) or use established sanitization libraries (like DOMPurify) when preparing user data for injection into raw HTML, especially within attribute contexts.
